# ping-metrika

Терминальный монитор ICMP ping на Go без внешних Go-зависимостей.
Требуется Go 1.23+ и системная команда `ping` (Windows, macOS или Linux с iputils).
Используется IPv4; имя разрешается один раз при запуске.

```sh
go build -o ping-metrika .
./ping-metrika example.com
./ping-metrika -interval 500ms -timeout 2s -slow 80ms 1.1.1.1
./ping-metrika -count 10 127.0.0.1
```

Windows: `go build -o ping-metrika.exe .`, затем `./ping-metrika.exe 1.1.1.1`.
Флаги указываются **перед адресом**. `-count 0` (по умолчанию) работает до остановки.
Нажмите **Ctrl+C**, в том числе на macOS, для завершения и вывода отчёта.
SIGTERM также завершает монитор с отчётом. Прерванная проба не считается потерей.

## Флаги запуска

| Флаг | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `-interval` | Длительность | `1s` | Интервал между началами проб. Должен быть больше нуля; если проба длится дольше интервала, следующая начинается после её завершения. |
| `-timeout` | Длительность | `2s` | Таймаут одной пробы. Должен быть больше нуля. |
| `-slow` | Длительность | `100ms` | Порог ухудшения: RTT больше или равный этому значению помечается как `SLOW`. Должен быть больше нуля. |
| `-count` | Целое число | `0` | Количество проб до автоматического завершения и вывода отчёта. `0` — работать до остановки; отрицательные значения запрещены. |
| `-h`, `-help` | Без значения | — | Показать справку и завершить работу. Адрес не требуется. |

Длительности задаются с единицами времени, например `500ms`, `2s`, `1m` или `1.5s`.
Значение можно передать через пробел или `=`, например `-timeout 3s` или `-timeout=3s`.
Адрес — обязательный позиционный аргумент после флагов: IPv4 или hostname.

## Отчёт

Отчёт содержит число ответов и ошибок, долю потерь/ошибок, min/avg/max RTT,
стандартное отклонение, p50/p90/p95/p99 и джиттер — среднюю абсолютную разницу
RTT соседних успешных проб (через потери разница не вычисляется).
Перцентили вычисляются линейной интерполяцией по успешным ответам.

Периоды ухудшения объединяют последовательные пробы с ошибками или RTT >= `-slow`
(по умолчанию 100 мс). Указываются начало, время первого нормального измерения,
приблизительная длительность, количество ошибок и пиковый RTT.
Последний незакрытый период явно помечается. Границы определяются по пробам,
поэтому точный момент начала/окончания сетевого сбоя неизвестен.

RTT берётся из ответа системного ping, без времени запуска процесса.
Для Windows `time<1ms` оценивается как 0.5 мс, поэтому статистика приблизительная.
Таймауты, блокировка ICMP и локальные ошибки учитываются вместе; строки ERROR
показывают причину. Пробы выполняются последовательно: если ответ занимает больше
интервала, следующая проба начинается после завершения предыдущей.
Измерения хранятся в памяти до остановки; потребление памяти растёт с длительностью.

Проверки: `go test ./...`, `go vet ./...`.
